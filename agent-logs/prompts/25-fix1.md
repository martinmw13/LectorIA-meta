## Bug 1 (blocking): AudioParam scheduling throws during a fade

`app/ambience-engine.ts` puts the sine fade-in curve (`setValueCurveAtTime`) and the later volume/mute `ramp()` and `stop()` on the SAME GainNode. `cancelScheduledValues(now)` does not remove a curve that started before `now`, so calling `setValueAtTime` / `linearRampToValueAtTime` while the 1.5 s fade-in or 2 s crossfade curve is still running throws `NotSupportedError` in Chrome/Safari (an event overlapping a value curve). Real repro: click rain to drizzle, then click again within 2 s (moderate) — the drizzle voice's `stop()` throws; or toggle mute / drag the rain volume during the fade-in.

Fix with a chain of three gain nodes per voice, so no node ever gets a second event that overlaps its curve:
`source -> fadeIn (sine 0->1 curve at start, or value 1 when fadeSec is 0) -> fadeOut (value 1; on stop, one cosine 1->0 curve) -> level (volume*mute gain; ramp() uses cancelScheduledValues + setValueAtTime(current) + linearRamp only on this node) -> destination`.
- `stop(sec)` must be idempotent: a second call does nothing (keep a flag). With sec <= 0 stop immediately (source.stop(now)) and disconnect.
- Disconnect all three nodes on `onended`.
- Wrap scheduling calls in try/catch only where a browser may still throw; do not swallow errors silently elsewhere.

## Bug 2 (non-blocking): crossfade is not equal power

Fade-in is a sine curve but the outgoing voice fades out linearly, so the mid-point sums to ~0.75 power (about -1.2 dB dip). With the fadeOut node above using a cosine curve (gain*cos(t*pi/2)) over the same CROSSFADE_SEC, the sum is equal power. Use the same cosine curve for fade-out to off (FADE_OUT_SEC).
