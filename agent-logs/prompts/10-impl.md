# Task 10 spec: English UI, one music mode, a skip icon and a now-playing line

Owner decisions (Martin, binding). The branch is stacked on task 8 (`scene-reader`, PR #9).

1. English only. Every user-facing string in the app becomes English, with nothing in Spanish anywhere. That covers the reader (task 8's pager: "Previous", "Next", "Chapter", the progress line, e.g. "Chapter 5 · The Rescue of the Tin Woodman · Scene 2 of 7 · Page 1 of 3"), the player, the picture panel and its states ("Illustrating…", "New", "Saved", the chat placeholder), API error messages returned to clients ("Images are unavailable right now.", the quota and budget messages), aria-labels, `<html lang="en">`, the page title and metadata. Update every test and every doc (docs/contracts.md, AGENTS.md product rules where they mention Spanish copy) that pins those strings. Error copy stays generic: no raw errors reach clients.
2. Renames: "Ilustrar este pasaje" becomes "Illustrate passage", "Ilustrar escena" becomes "Illustrate scene", the style selector is labelled "Orchestra / Piano", and "Just play Chopin" stays.
3. Remove soundtrack mixing entirely: no "Mezclar bandas" and no switch. Selection always picks from ALL tracks in the current style that fit the scene's emotion, across soundtracks, using the existing scoring (today's cross-soundtrack "random" behaviour becomes the only one). Delete the "soundtrack" (keep same soundtrack) mode, `MusicSelection.mode`, `soundtrackId` if nothing else needs it, `PersistedMusicPrefs.mode`, `mixOffSelection` and their tests. Old localStorage values must load safely: ignore unknown or obsolete fields and keep a valid `style`. Keep the no-immediate-repeat rule and its tests. Keep the Orchestra / Piano style switch and the Chopin playlist.
4. Player transport is three standard media icon buttons, inline SVG (`currentColor`), one consistent size (about 32 px hit area, 16 to 18 px icon), quiet neutral, Meta blue on hover and focus-visible, each with `aria-label` and `title`; no text buttons:
   - Previous track (⏮): goes back to the previously played track in this session's history; with no history it restarts the current track from 0. Keep the history in a pure core helper (a bounded stack of played track ids; Next and automatic switches push, Previous pops) and tell the scheduler about the manual pick through a pure entry point in core/music-schedule.ts that mirrors how `requestNext` sets `currentId` (a manual hold, so the scene logic does not switch away at once). Test it.
   - Play/Pause (▶/⏸): one toggle; the icon and the `aria-label` switch between "Play" and "Pause".
   - Next track (⏭): still cycles same-emotion tracks within the style and falls back to the next-best track.
5. Now-playing line in the player: one understated line, `title · composer or artist · source` (e.g. "Symphony No. 3 – III · Brahms · Musopen / CNSO"). Source comes from the track's attribution or its soundtrack credit, whichever the manifest provides; skip missing parts without leaving stray separators. One line, truncated with an ellipsis, with the full credit (including license) in a `title` tooltip. It updates when the track changes (crossfades included). Keep any license/source link the manifest requires, but compact. Build the line in a pure helper with tests.
5b. Image actions (replace the companion side panel):
   - "Picture scene": a small, elegant text button at the very top of each scene view, on the progress line row, right-aligned (not in a side panel, not floating). It requests the scene image for the route's scene id.
   - "Picture this": a small popover next to a mouse text selection, matching the original Lectoria's behaviour: it appears on mouseup (after a requestAnimationFrame) only when the trimmed selection is at least 3 characters and lies inside the scene text; it is centred horizontally above the selection with a small arrow (absolute inside the scene view: x = selection centre, y = selection top minus 8 px, translate(-50%, -100%)); any mousedown outside the popover dismisses it, and so do Escape, a sub-page or scene change, and starting a request. It sends ordinals only (the existing `pickStartN` path), never text. Hidden while an image is loading.
   - Result placement: inline under the scene heading, inside the scene view, at most about 320 px tall (`object-fit: contain`), with its caption, a small "New"/"Saved" tag and a dismiss (×) button; loading and error states sit in the same slot. Why: the scene view becomes one clean centred column, the image sits next to the text it illustrates (as in the original), and the side panel had nothing else to hold. Remove the companion aside and the chat placeholder line; the image stays for the current scene across its sub-pages and clears on scene change.
   - Keep the image API, cookies, quota and budget logic unchanged apart from English copy; keep the image tests passing (update the strings they pin).
