# Task 11 spec: re-split scenes at strong sequential emotion shifts

Owner decision (Martin, binding): a scene must not change mood halfway (calm, then the cyclone), because music only changes at scene boundaries. Split a scene ONLY where the dominant emotion changes strongly and persistently along the text. A simultaneous blend (bittersweet: calm with some sadness) is NOT a reason to split: it stays as the per-scene probability vector + intensity + tempo, and that model does not change. Pages inside a scene stay only for length. Avoid over-splitting.

Today: `pipeline/segment.ts` asks Meta for "one dominant mood" per scene and nothing checks it. Oz has 133 scenes; 28 have top final probability < 0.5, 17 have a top-2 gap < 0.15; lengths 53 to 845 words (median 269), 42 over 350 words.

1. New pipeline step `resplit`, after `classify` and before `cluster` (`npm run build:book -- oz --step resplit [--force]`; it also runs in the full sequence). It reads book.json and analysis.json and rewrites scenes.json and analysis.json.
2. Candidates: scenes with more than 350 words, or top final probability < 0.5, or top-2 gap < 0.15, or `final === null` is NOT a candidate (no vector, leave it). Scenes under 240 words are never split (both parts must reach the minimum).
3. Windows: cut the candidate into consecutive windows of whole paragraphs, greedily about 100 to 160 words each (a single long paragraph is its own window). Classify each window with the existing Jev client (same questions, model jev-1.14.0; extend `JevClient` minimally if you must, keep the `model` field in every request). Drop `unknown` and renormalize to the 8 ids with the existing helpers.
4. Split rule, pure and in `core/` (no network, unit-tested with fixed vectors). For a candidate boundary between windows, let L be the word-weighted mean vector of all windows on the left and R the same on the right (within the current segment). With a = argmax L, b = argmax R, a != b: margin = min(L[a] - L[b], R[b] - R[a]). Constraints: each side at least 120 words AND at least 2 windows or 120 words of one window (persistence: the new mood must hold, not spike in one short window). Pick the boundary with the largest margin; then recurse on each side (binary segmentation) with the same rule. Thresholds as named constants:
   - margin >= 0.30: split automatically.
   - 0.15 <= margin < 0.30: ambiguous, ask Muse (Meta, structured JSON `{ split: boolean, reason: string }`) with the text around the boundary (last ~2 paragraphs before and first ~2 after, plus both vectors). Muse decides only these.
   - margin < 0.15: no split.
   Tune these two numbers only if the Oz run shows clear over- or under-splitting, record the final values and why in the task doc. Target: a modest number of splits (a rough sanity range is 5 to 30 on Oz), never a split that leaves a part under 120 words.
5. New scenes: for each split scene, the FIRST part keeps the original id (old links and bookmarks keep working); later parts get the same id with a letter suffix: `c5s2b`, `c5s2c`. Unsplit scenes keep their ids and records untouched. One Meta call per split scene gives each part a title, summary and characters (structured output; English titles in the style of the existing ones). Then re-classify every new part with the full existing classify path (Jev, plus the Muse override on low confidence: reuse `classifyScene`, export it, do not duplicate it).
