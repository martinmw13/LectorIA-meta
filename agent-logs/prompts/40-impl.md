## Goal
Read-aloud narration, voice Kokoro-82M (Apache-2.0) `af_heart`, speed 0.95, generated on a Modal GPU function that scales to zero. The unit is the CHAPTER (owner decision): one compact mp3 per chapter plus a per-chapter manifest with sentence timings, so the reader can play any scene by seeking to its first sentence and can highlight the sentence being read. One reusable function, `ensureChapterNarration`, is used offline for Oz now and later on demand for uploaded books. Every chapter's audio lives under a content-addressed cache key, so a second reader of the same book (or the same Oz text) gets it free.

## 1. `core/narration.ts` (pure, no env, no network, no node: imports) + tests
- Constants: `NARRATION_VOICE = "af_heart"`, `NARRATION_MODEL = "kokoro-82m/0.9.4"`, `NARRATION_SPEED = 0.95`, `NARRATION_FORMAT = 1`, `SENTENCE_GAP_SEC = 0.3`, `PARAGRAPH_GAP_SEC = 0.7`.
- `splitSentences(text: string): { start: number; end: number }[]`: char offsets into the paragraph text, trimmed of surrounding whitespace, covering every non-space char. A sentence ends at `.`, `!` or `?` (also `…`), plus any closing quotes/brackets (`”’"')]`), followed by whitespace. Do not end after common abbreviations (Mr. Mrs. Dr. St. Mt. etc. — keep a small list) or a single capital initial. Merge a piece shorter than 3 words into the previous sentence (or the next one if first). Test with real Oz-style text containing curly quotes, em dashes, "Mr.", "!” said Dorothy", and a quote ending a paragraph.
- `NarrationChunk = { n: number; start: number; end: number; text: string }` and `chapterChunks(paragraphs: { n: number; text: string }[]): { chunks: NarrationChunk[]; gaps: number[] }`. `gaps[i]` is the silence after chunk i: `PARAGRAPH_GAP_SEC` when the next chunk is a new paragraph, `SENTENCE_GAP_SEC` otherwise, 0 after the last.
- `narrationKeyInput({ chunks, voice, model, speed, format }): string`: a canonical string built from the NFC-normalized, whitespace-collapsed chunk texts (joined with "\n"), voice, model, speed and format. Callers hash it with SHA-256 (core takes no crypto); `narrationKey(hashHex: string, voice: string): string` returns `narration/v${NARRATION_FORMAT}/${voice}/${hashHex.slice(0, 32)}`. Audio path is `${key}.mp3`, manifest path `${key}.json`. Same text + voice + model + speed => same key, any edit => new key (test it).
- `ChapterNarration = { format: 1; key: string; src: string; durationSec: number; voice: string; model: string; speed: number; chunks: { n: number; start: number; end: number; t0: number; t1: number }[] }` and a strict `parseChapterNarration(json: unknown): ChapterNarration` that throws on any bad field (it is a trust boundary: the reader fetches it). `src` must be an `https:` URL or a same-origin path starting with `/narration/`. Times finite, `0 <= t0 < t1 <= durationSec + 0.05`, chunks sorted by t0, n integers, start < end.
- `activeChunkAt(chunks, tSec): number`: binary search, index of the last chunk with `t0 <= t` (so the highlight stays on a sentence through the gap after it), -1 before the first chunk.
- `sceneSpan(narration, startN, endN): { startSec: number; endSec: number } | null`: from t0 of the first chunk with `n >= startN` to t1 of the last chunk with `n <= endN`; null when no chunk falls in the range.
- `chaptersToPrepare(event: "upload" | "enter" | "jump", ch: number, totalChapters: number): number[]` (owner's rolling window): upload => [1, 2]; enter chapter N => [N+1, N+2]; jump to N => [N, N+1]. Clip to 1..total, dedupe, keep order.
- Cost: `KOKORO_L4_USD_PER_SEC = 0.000222` (Modal L4, about USD 0.80/h) and `estimateNarrationMicro(chars: number): number` = ceil((chars / 15 * 0.02 + 8) * KOKORO_L4_USD_PER_SEC * 1e6): about 15 chars of audio per second, GPU time about 2% of audio after encode, plus 8 s of cold start/overhead. `actualNarrationMicro(gpuSec)` = ceil(gpuSec * rate * 1e6). Integer micro-dollars, as the repo rules require.
- `ensureChapterNarration(input: { chunks: NarrationChunk[]; gaps: number[]; voice?: string; speed?: number }, deps: NarrationDeps): Promise<EnsureResult>` with
  ```ts
  interface NarrationDeps {
    sha256Hex(text: string): Promise<string>;
    index: { get(key: string): Promise<ChapterNarration | null>; set(key: string, value: ChapterNarration): Promise<void> };
    store: { getManifest(key: string): Promise<ChapterNarration | null>; putAudio(key: string, mp3: Uint8Array): Promise<string>; putManifest(key: string, value: ChapterNarration): Promise<void> };
    lock?: { acquire(key: string): Promise<string | null>; release(key: string, token: string): Promise<void> };
    budget?: { reserve(micro: number): Promise<boolean>; refund(micro: number): Promise<void> };
    synthesize(req: { texts: string[]; gaps: number[]; voice: string; speed: number }): Promise<{ mp3: Uint8Array; durationSec: number; spans: { t0: number; t1: number }[]; gpuSec: number }>;
  }
  type EnsureResult =
    | { status: "ready"; narration: ChapterNarration; cached: boolean; costMicro: number }
    | { status: "pending" }
    | { status: "error"; code: "budget" | "failed" };
  ```
  Flow, in this order: key => `index.get` hit => ready cached, cost 0, no lock, no budget. Miss => `store.getManifest` hit => `index.set` backfill, ready cached. Miss => `lock.acquire` (null => pending). Then re-check the index once (another holder may have just finished). Then `budget.reserve(estimateNarrationMicro(totalChars))` (false => release, error budget). Then synthesize (validate `spans.length === texts.length`, else failed), putAudio, build and validate the manifest with `parseChapterNarration`, putManifest, index.set, release, return ready with `cached: false` and `costMicro` = the reserved estimate (the cap counts what was reserved; never refund on success). Any throw after the reserve => refund once, release, error failed. Release failures are swallowed (the lock has a TTL). Never put error text in the result. Spend is counted only when audio is generated, never on hits. Tests with in-memory fakes: hit from index, hit from store with backfill, concurrent second caller gets pending while the first holds the lock, budget refusal releases the lock and never synthesizes, synthesize/store failure refunds exactly once and releases, success counts the estimate, a second call after success is a free hit, and the manifest timings round-trip through `sceneSpan` and `activeChunkAt`.
Split into `core/narration.ts` and `core/narration-cache.ts` (or similar) if a file would pass the size hook; tests likewise.
