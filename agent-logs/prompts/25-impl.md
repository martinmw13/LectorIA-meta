3. app/ambience-controller.ts: class AmbienceController built on an injected engine interface:
   - engine.load(sources) -> Promise<handle> (the engine picks the playable source and decodes it; cache by src),
   - engine.start(handle, gain, fadeSec) -> voice, voice.ramp(gain, sec), voice.stop(fadeSec),
   - engine.unlock() -> Promise<void> (resumes the AudioContext; must be called from a user gesture).
   Controller API: setLevel(id), setVolume(v), setMuted(m), unlock(), dispose(). Rules: switching from off fades in over FADE_IN_SEC; switching between two playing levels crossfades (old voice stop(CROSSFADE_SEC) while the new one starts at 0 and ramps up over CROSSFADE_SEC); switching to off stops with FADE_OUT_SEC; volume changes ramp over 0.1 s; mute and unmute ramp over MUTE_FADE_SEC; while locked (no unlock yet) nothing starts, and the first unlock starts the current level. Async loads must not race: if the level changes while a load is pending, only the latest level may start. Never more than two voices alive. Tests in app/ambience-controller.test.ts with a fake engine: full cycle off->drizzle->moderate->storm->off, crossfade timings, fade in and out, mute silences and unmute restores at the set volume, volume ramp, locked state does not start until unlock, rapid clicks start only the final level, dispose stops everything.

4. app/ambience-engine.ts: real engine with Web Audio. One lazily created AudioContext. load: choose the first source whose type `new Audio().canPlayType(type)` answers "probably" or "maybe", fetch it (same origin), decodeAudioData, cache the promise by src. start: AudioBufferSourceNode with loop = true into a GainNode into destination; fades with setValueAtTime(current) then linearRampToValueAtTime on the audio clock (equal-power is not required here; for the crossfade use setValueCurveAtTime with a sine/cosine curve of 32 points). stop: ramp to 0 then source.stop at the end and disconnect. No test needed beyond a type check.
