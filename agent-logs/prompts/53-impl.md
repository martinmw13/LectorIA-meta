## Goal
Native, smooth, momentum CONTINUOUS SCROLL through the whole book, organised by scene:
1. The reading column renders the whole book (all chapters, all scenes, all paragraphs) as one long scroll. Each chapter starts with its kicker/number + chapter title + the existing Chapter in panels strip (PanelsOfferCard / PanelsQuietLink, spoiler gate kept) inline, immediately followed by the chapter text. No Begin button, no "or just scroll" hint. Scene boundaries are natural breaks (a section per scene, e.g. `<section data-scene-id>` with a light divider/ornament between scenes; keep the "Scene k of n" line subtle or drop it if it adds noise). At a chapter's end keep a light "Relive this chapter in panels" entry inline (no full-screen end page) and the text simply continues into the next chapter. Book end shows "The end."
2. Delete the wheel hijacking (scene-page wheel listener, inNestedScroller, wheelState, app/folio/scroll-turn.ts and its test if nothing else uses it), the paged sub-page model in the reader UI (pagination, enterAtEnd, readOn cues, sub-page progress), and the keyboard page-turn handler. Space / PageDown / PageUp / arrows / Home / End work through NATIVE scrolling: make sure the scroll container is the thing that receives keys (either let the document/body scroll, or keep .read-col as scroller but focus it on load with tabIndex=-1 and no focus ring). Prefer whatever gives true native momentum on trackpads and the least code. Remove now-dead pure helpers in core/reader (paginateScene, subPageCount, navReducer, etc.) only if no other caller and tests remain, else leave them.
3. Current scene = the scene section most in view, tracked with ONE IntersectionObserver (no scroll listeners doing layout reads; if any scroll listener is unavoidable it must be passive and rAF-throttled). The current scene id drives: music sceneEntered transitions in app/reader.tsx (keep the existing session dwell/gate semantics), the Picture this scene card + selection popover anchored to the scene in view (never offered on a chapter heading/strip area), the vault, the BandPager/progress ("scene x of y"), and the URL: update it with `window.history.replaceState` to `/leer/<sceneId>` (Next 16 syncs native history with usePathname/useParams; verify Reader sees it — if not, share current scene via a tiny context/store instead). Do not router.push per scene (no remounts while scrolling).
4. Resume: loading /leer/<sceneId> scrolls instantly (no animation) to that scene's section; also remember the last scene in localStorage (key under the existing namespace style) and, when landing on /leer/c1s1 or /read/oz with nothing explicit... keep it simple: only the URL is required; localStorage resume is optional, skip if it complicates.
5. BandPager prev/next and chapter jumps: scroll to the target section (smooth unless prefers-reduced-motion, then instant). All programmatic smooth scrolling respects prefers-reduced-motion.
6. Perf: no layout thrash on scroll. Lazy images (`loading="lazy" decoding="async"` on inline figures / panel thumbs). Add `content-visibility: auto; contain-intrinsic-size: auto 1200px` (or similar) on scene sections so a full book stays smooth; check that IntersectionObserver and anchor scrolling still work with it (contain-intrinsic-size `auto` keeps remembered sizes). Remove any CSS scroll-snap / scroll-behavior that fights momentum.
7. Narration auto-follow (for the narration UI another agent is building on top of PR #46 word timings): export a small helper, e.g. `followIntoView(el, scroller)` in app/leer/ or app/folio/, that scrolls the spoken word into view only when it leaves a comfortable band, and pauses auto-follow for ~4 s after any user wheel/touch/key scroll (passive listeners). Unit test it. Do not build the narration UI.

Make it work per scene in view (simplest: pass the current scene id; figures/popover attach to the text container of that scene; selections in another scene switch the current scene). Keep the PR #42 callback-ref behaviour. Picture this is never offered on chapter headings.
