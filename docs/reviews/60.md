# Review 60: read-along render isolation

Written and verified by Grok Bot (mechanical refactor, no Muse round).

Verdict: approved.

## Problem (architecture review after #57)

`BookView` called `useNarration()` and `useReadSync()` itself. The
controller object is new on every provider render and the word clock
lives in `useReadSync` state, so every word, volume step and duck-ramp
frame re-rendered the whole book: every chapter, scene and paragraph.

## Fix

- New `app/narration/read-along.tsx`: `<ReadAlong columnRef>` reads the
  narration context, runs `useReadSync` and renders `<ReadMark>`.
- `BookView` renders `<ReadAlong columnRef={readColRef} />` inside
  `.read-col` where `<ReadMark>` was, and no longer imports the narration
  context. Behaviour is unchanged: same options, same mark position.

## Verification

- `app/leer/book-view-renders.test.tsx` (jsdom) mounts the real
  `NarrationProvider` and `BookView`, plays, drives `timeupdate` across
  words and changes the volume. A context probe re-renders each time;
  `BookView` renders zero extra times. On the old `book-view.tsx` the same
  test fails (13 renders instead of 2).
- vitest under Node 22, typecheck, build, check:size, check:isolation,
  check:secrets, gitleaks.
- `scripts/e2e-narration.py` and `scripts/e2e-scroll.py` pass locally.
