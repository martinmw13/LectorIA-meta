# Review 32: pictures placement

Source: docs/tasks/32-pictures-placement.md and agent-logs/prompts/32-impl.md
(architecture review 5, candidates 1 and 2). Hard requirement: user-visible
behavior identical (same DOM, classes, copy, request bodies, timing, same
request ordering).

What this change does: figure placement (`groupFiguresByEndN`,
`figuresAfter`, `pageOfOrdinal`) and the request gates (`tryStart`/`finish`,
`canStart`, `canRetryFigure`, `canIllustrateScene`) move into pure
`app/folio/figure-placement.ts`, used by `scene-page.tsx` and
`use-pictures.ts`; `pref` becomes a hook argument read through a ref; the
lightbox trio becomes `lightbox: { item, open, close }`; the icon and strings
move to `picture-copy.tsx`; `THEME_KEY` moves to `app/theme.ts` with
`THEME_SCRIPT` interpolated. Tests cover the placement rules, the gates, and
the theme script.

1. `requestFigure` ignores the `tryStart` return (`app/folio/use-pictures.ts:164`).
   What this is: `tryStart(busyRef);` runs, then `poll(...)` starts no
   matter what it returned. If it ever returned false, the second request
   would still fly, and its `.finally(finish)` would clear `busy` while the
   first request is still in flight, opening the gate for a third.
   Today it cannot happen: both callers (`illustratePassage` via `canStart`,
   `retryFigure` via `canRetryFigure`) check `busy` synchronously in the
   same tick, so `tryStart` inside `requestFigure` always succeeds, exactly
   like the old unconditional `busyRef.current = true`. Behavior is
   identical, but the atomic check-then-act the extraction was meant to buy
   lives in the callers instead of the return value.
   If we skip it: a future caller that trusts `tryStart` to guard will get
   double requests and a corrupted gate. Should fix: check the return
   (`if (!tryStart(busyRef)) return;`) and keep a comment that the callers
   pre-check, or drop `tryStart` from `requestFigure` and say the callers own
   the gate. Note the wrinkle: `illustratePassage` inserts the loading figure
   before calling `requestFigure`, so an early return there must run before
   the insert, or it orphans a loading figure.
2. The `figuresAfter` doc comment contradicts the code and the test
   (`app/folio/figure-placement.ts:11-14`).
   What this is: the comment says a paragraph split across pages shows its
   figures "only on the page holding its last visible fragment there". The
   code is per-page-local (`paragraphs[i + 1]?.n !== cur.n`), so each page's
   last visible fragment of that ordinal renders the figures, on both pages.
   The test (`figure-placement.test.ts:44-53`) pins the true both-pages
   behavior, which matches the old inline code exactly.
   If we skip it: someone will "fix" the code to match the comment and break
   the second page's figures. Should fix: one-line comment correction to say
   each page renders after its own last visible fragment.
3. `prefRef.current = pref` runs during render (`app/folio/use-pictures.ts:113-114`).
   What this is: the ref is written in the render body instead of an effect.
   The value read at event time equals the old per-call argument (the caller
   passed the current `pref` state at click time; the ref holds the latest
   rendered one), so bodies, credit, and timing are identical, and the
   callbacks stay stable as claimed. Only concurrent-render tearing could
   ever show a stale pref, and this tree has no path that triggers it.
   Nice to have: assign in `useEffect`, or keep with a one-line why.
4. Placement matches the old inline code exactly
   (`app/folio/figure-placement.ts:15-29`, `app/leer/scene-page.tsx:310`).
   What this is: `figuresAfter` is the old ternary verbatim, including the
   out-of-bounds case (`arr[i + 1]?.n !== p.n` is true past the end) and the
   `?? []` miss case; `pageOfOrdinal` is the old `findIndex`, `-1` included.
   The DOM side of `gotoFigure` (setPage, scroll, pulse) stayed in
   `scene-page.tsx` and now calls `pageOfOrdinal`. Verified by reading both
   sides of the diff. No change.
5. The busy gate blocks both ways and always releases.
   What this is: scene-while-figure blocked by `canIllustrateScene`'s `busy`
   check, figure-while-scene by `canStart`, retry-while-busy by
   `canRetryFigure`; every `tryStart` success pairs with `.finally(finish)`,
   and every early return happens before `tryStart`, so `busy` cannot stick.
   Retry only from `error`, scene refused when cached or id-less: truth
   tables match the old inline conditions (`!sceneId || busy || cached`,
   `phase !== "error"`). No stuck path, no double-start path, same as
   before. See finding 1 for the latent-only gap.
6. `pref`-through-ref carries the same value the old per-call argument did.
   What this is: scene retry, figure retry, and credit all read
   `prefRef.current` at event time, which equals the `pref` state the old
   call sites passed at the same moment. `requestStyleFields`/`styleCredit`
   inputs unchanged, so request bodies are byte-identical.
7. Lightbox grouping breaks no caller.
   Blast-radius (skill disabled, grepped by hand): `usePictures` has exactly
   one caller (`scene-page.tsx:78`); `openLightbox`/`closeLightbox` appear
   nowhere else; all five use sites moved to `pic.lightbox.open/close/item`
   (`scene-page.tsx:238,316,341,355,363`); `Lightbox` props (`item`,
   `onClose`) untouched; the returned object was already fresh per render,
   so memoization is unchanged. `typecheck` is clean.
8. Icon sizes and strings preserved; no "Generated".
   What this is: `image-pane.tsx:61,70` use the shared default 13 (was a
   local 13), `inline-figures.tsx:27` passes `size={12}` (was a local 12);
   the SVG body is verbatim, and React renders numeric 13/12 to the same
   attributes. `Sketching…`, `Try again`, `Remove picture` moved to
   `PICTURE_COPY` byte-identical (ellipses and all); class names untouched.
   The `copy-gates` suite scans all of `app`/`core` for "Generated" and
   passes.
9. `THEME_SCRIPT` output is byte-identical and LIGHT stays the default
   (`app/theme.ts:6-12`).
   What this is: `JSON.stringify("lectoria.theme")` renders
   `"lectoria.theme"`, so the evaluated string equals the old literal
   (verified by comparing the old file's script against the interpolated
   reconstruction in node: identical). `initialTheme` untouched;
   `chrome.tsx:7` re-exports, so `reader.tsx` (still importing from chrome)
   needed no edit and keeps working. New theme tests evaluate the script
   with null, "garbage", "dark", "light", and a throwing localStorage, all
   resolving as specified.
10. Tests are meaningful (`app/folio/figure-placement.test.ts:1-105`,
    `app/theme.test.ts:18-48`).
    Placement: insertion order per endN, whole paragraph, last-fragment-only
    on one page, both-pages split (documents current behavior, does not
    change it), multi-figure, none, found/later-page/missing ordinal. Gates:
    scene-blocks-figure and vice versa, finish releases, retry refused from
    loading/ready/busy/undefined and allowed from error, scene refused when
    cached or id-less. Each fails if the rule breaks. Not pinned: the exact
    copy strings and icon sizes (single-sourcing makes view drift
    impossible; only the shared const could change, which the "Generated"
    gate and review catch).

Checks: `npm test` (45 files, 397 tests pass), `npm run typecheck` (clean),
plus a node probe of old-vs-new `THEME_SCRIPT` (identical) and grep over
callers, `Generated`, and `THEME_KEY` uses. Did not run `next start`, build,

user-visible behavior today.
