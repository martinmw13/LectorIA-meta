## Non-blocking findings

1. Next is pinned to 16.1.0, not the latest 16.x (16.4.3). The build passes and Vercel will build it, so this does not block. The fix is one line in `package.json` (`"next": "16.4.3"`, then `npm install` to resync the lockfile) to pick up later fixes before the app grows. Do it once, not on every patch.
2. `@types/node` is 26.6.5 while the runtime is Node 22. The build passes, but the types can admit APIs that do not exist on Node 22. Consider pinning `@types/node` to a 22.x line in `package.json`.
3. `docs/spikes.md` says the cyclone passage splits between aventura 0.48 and asombro 0.38, but the Jev table only lists choice and confidence (aventura 0.41). The numbers presumably come from the script probs line, which the doc does not reproduce. Either add the full 8 id vector per passage to the table or drop the two numbers.
4. `next.config.ts` sets `connect-src 'self'`, which is right for a skeleton with no client fetches. When Turnstile is added later, its client calls to `challenges.cloudflare.com` will need a `connect-src` entry too. No change now.
5. The reader shell has no skip link and the fixed 18rem side panel will squeeze on narrow screens. Owner rule is desktop first, so this is fine for a skeleton. Add a skip link when the reader becomes interactive.
