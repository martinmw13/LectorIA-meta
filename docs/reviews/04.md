# Review: task 4 Oz pipeline

Verdict: approve with fixes. No blocker. Fix findings 1 and 2 before any app code reads these data files; fix 3 to 5 before the soundtrack step runs for real.

What this change does: ingests the Oz text into `book.json`, splits chapters into scenes with Meta, classifies each scene with Jev plus a Meta override on low confidence, and clusters scene vectors into 15 track prompts. New code in `core/` and `pipeline/`, committed data in `data/books/oz/`, with tests beside each module.

## Findings

1. **Stored Jev fields use camelCase against the snake_case spec** (should-fix), `core/types.ts:59-70`, `data/books/oz/analysis.json`.
   Problem: the spec asked for `intensity_confidence` and `tempo_confidence`, but the stored scenes carry `intensityConfidence`, `tempoConfidence`, `inputTokens`, `outputTokens`, while provenance in the same file uses `prompt_tokens` and `cached_tokens`. One file mixes two conventions.
   Fix: rename the stored Jev fields to snake_case in `JevResult`, update the two readers (`pipeline/classify.ts`, `pipeline/jev.ts`), and rewrite `analysis.json` from the next classify run.

2. **Sad and dark clusters never get the minor-key variant** (should-fix), `core/music-prompt.ts:6-7, 32-44`.
   Problem: the spec asked for minor variants for sad or dark moods, but the base hardcodes "in a major key" and `buildTrackPrompt` has no mood branch. The grief cluster (t05, tristeza 0.86) and the dread cluster (t08, suspenso/tristeza) both ship major-key prompts.
   Fix: switch the base to a minor-key leitmotif when the top mood is tristeza, suspenso, or misterio, and keep major otherwise. One branch, no new module.

3. **Two cluster pairs yield near-identical prompts** (should-fix), `data/books/oz/music-clusters.json` t12/t13 and t14/t15.
   Problem: t12 and t13 carry the same mood text ("driving and fierce, tense and expectant") with the same dynamics and differ only in BPM; t14 and t15 use the same two mood words in swapped order. Fixed k=15 splits tiny groups (t08 and t12 hold 2 scenes each), and the prompt template has too few degrees of freedom to tell them apart.
   Fix: after sorting, merge clusters whose top-two moods match and whose BPM ranges overlap, or widen the template (dynamics, register) so centroids this close still read differently.

4. **Dynamics buckets call fight scenes "moderate"** (should-fix), `core/music-prompt.ts:26-30`.
   Problem: three coarse buckets put intensity 0.49 (t12), 0.54 (t13), and 0.63 (t08) all under "moderate dynamics". The fiercest scenes in the book get the same dynamics word as a calm river rest.
   Fix: cut the top bucket at 0.5 instead of 0.67, or word dynamics from the dominant emotion as well as intensity.

5. **Meta retries stack three deep** (should-fix), `pipeline/meta.ts:42-52`, `pipeline/segment.ts:90`.
   Problem: `completeJson` loops 3 attempts around `fetchWithRetry` with `attempts: 3`, so one call can fire up to 9 requests; the segment validation retry doubles that to 18 per chapter. The spec asked for 3 attempts with backoff plus one retry on invalid output.
   Fix: keep one loop. Drop the outer for-loop in `completeJson` and let `fetchWithRetry` own network retries; keep the single validation retry in segment.

6. **Unused error parameter in the retry check** (nit), `pipeline/http.ts:8`.
   Problem: `isRetryable(status, _error)` takes an argument it never reads, so future callers will guess what it is for.
   Fix: delete the parameter and update the two call sites.

7. **Cluster scene lookup is quadratic** (nit), `pipeline/cluster-tracks.ts:39-43`.
   Problem: `classified.find` runs per point per cluster. At 133 scenes this is instant, but it is a needless nested scan.
   Fix: build one `Map` from scene id to scene before the cluster loop.

## Checked and fine

- Core purity: no `process.env`, `node:` imports, `fetch`, or `fs` in `core/`. Secrets stay in env, read only in `pipeline/build.ts`. Errors carry status plus a short body excerpt; no headers or keys are logged. No MusicGen, Modal, or audio code anywhere.
- Scene coverage (recomputed on the committed files): 24 chapters, 1104 paragraphs with sequential `n`, 133 scenes, 0 gaps, 0 overlaps, 0 chapter crossings. All range logic compares `n`.
- Failure handling: 0 hard failures, 0 null finals, `unclustered` empty. Every final vector sums to 1. Every override vector holds exactly the 8 ids. The override rate is 33.8% (45 of 133), all from genuine low confidence or `unknown`-max cases in the spot check.
- Scene plausibility: the cyclone reads tristeza, suspenso, asombro, then calma, in order. The poppy Meadow reads calm and bright before the sleep scene turns to suspenso. The Winged Monkeys arc moves from lost (tristeza/aventura tie) to summoning (aventura/asombro) to arrival (alegria). The Kalidah attack fits except for one soft edge: the book's clearest fight scene lands suspenso 0.83 with combate only 0.16, so the energy sits in intensity 0.72 and tempo 0.89 rather than in the vector.
- Tests prove behavior: `npm test` passes 31/31, including override, hard-failure-stores-no-vector, determinism, and the committed-data test. `npm run typecheck` is clean. Cost math matches the spec rates by hand: Jev 134284 input tokens at 0.042 per 1M gives $0.0056; Meta 86521 prompt with 11025 cached plus 60080 completion at 0.10/0.002/0.20 gives $0.0196; total $0.0252, under the $0.10 budget.
- Config: only the four allowed devDependencies, scripts match the spec, size ignore plus test cover `data/books/`, hook tests pass 40/40, secret scan exits 0, size check passes.
