## Non-blocking findings

1. One committed track title is Spanish: `public/music/manifest.json:1323` and `data/music/library.json:367` carry `"Un ratón en el escenario"` for `jamendo-961892`, repeated in the attribution at `public/music/manifest.json:1344`. The spec asks for English user-facing strings, but this is the work's published Jamendo title, so translating it would misattribute the track. Suggested fix: keep the original title and record an owner exception to the English rule for published work titles. Proper nouns with accents elsewhere (Lévy, Grégoire Lourme, Pathétique, Vltava) fall under the same exception and need no change.
2. The v2 manifest fallback still names its implicit style `Orquesta` in `core/music-manifest.ts:61`, while `docs/contracts.md` now describes style names as English display names. The v2 path is legacy only and no committed v2 file remains. Suggested fix: rename to `Orchestra` or leave it, since nothing reads v2 input.
3. `pipeline/labels-to-manifest.ts:217-222` casts `styles`, `soundtracks`, `playlists`, and `extraTracks` without deep checks and relies on the final `parseManifest` call to reject bad shapes. This works because the result is validated before writing, but a malformed library style fails with a manifest error rather than a library error. Suggested fix: none required; only tighten if library authors hit confusing messages.
