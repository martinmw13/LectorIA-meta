# Review 86: upload processing backend

Reviewer: Grok Bot (orchestrator). Code by Muse Code (muse-spark-1.3).

- Order in the handler: same-origin JSON check, body cap, strict zod parse,
  env, Turnstile, anon cookie, BYOK header, then quota and spend (free only).
- Caps: 2 books/day per hashed IP or anon cookie (whichever hits first),
  USD 1/day global under `upload:spend:daily:<day>`, also inside the overall
  spend cap. Flat USD 0.25 reserve, adjusted to the measured cost at finalize.
- Refunds: create refunds on any throw after the reserve; a failed step
  refunds once (guarded), a finished job never refunds.
- BYOK key: header only, validated, kept in memory, never in Redis, Blob or
  logs. BYOK jobs never use our Jev key.
- Model output goes through zod schemas and clamps; nothing renders as HTML.
- Blob: dedicated private store (`UPLOADS_BLOB_READ_WRITE_TOKEN`), no
  fallback to the public store, 128-bit `u-` ids, 30-day cleanup cron.
- Timeouts: Blob 8s, Redis 5s, clean judge bounded to 25s, step calls bounded.
- Real e2e (Velveteen Rabbit, 3,955 words, contributor + Jev): 1 chapter,
  9 scenes, USD 0.002674, one 24.9s step.

Known limits: an abandoned job keeps its reserve until the day rolls over;
a step that outlives 60s is retried by the client after the 120s part lock.
