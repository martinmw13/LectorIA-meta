# Review 40: chapter narration (pipeline, cache, contract)

Reviewer: Grok Bot (orchestrator). Implementer: Muse Code (Contributor).

## Round 1

Gates passed on the first run (tests, typecheck, size, secrets, hooks,
dry-run, py_compile). Findings:

1. `pipeline/modal/narrate.py` imports numpy and soundfile at module
   top level, so `modal deploy` fails on a machine without them. Move
   them under `with kimg.imports():`.
2. A sentence Kokoro renders as no audio (for example "…") gives
   `t0 == t1`, which `parseChapterNarration` rejects, so the whole
   chapter fails. Give every span a floor of 50 ms of silence.
3. `runNarrate` records `keys.current` as `provenance.input` after an
   incomplete run when there is no previous file. The next run would
   then say "reuse" over missing chapters. An incomplete run must record
   no input.
4. One failed chapter rejects `Promise.all` and nothing is written, so
   paid chapters are lost from narration.json. Keep going, write the
   ready chapters, mark the run incomplete, and exit non-zero.
5. `pipeline/kokoro.ts` rethrows the raw Modal error. Throw only the
   generic message so nothing from the SDK reaches logs.

### Fixes

1. `pipeline/modal/narrate.py`: numpy/soundfile moved under
   `with kimg.imports()`, plus `from __future__ import annotations`
   so annotations stay lazy. Verified with `py_compile`.
2. `pipeline/modal/narrate.py`: each span padded to a 50 ms floor
   (`MIN_SPAN_SAMPLES`), with a short comment. Verified with
   `py_compile`.
3. `pipeline/narrate.ts`: incomplete runs write
   `provenance.input: null`, so the next run redoes instead of
   reusing a partial file. Covered by the one-chapter-failure test
   (`input` null, retry regenerates).
4. `pipeline/narrate.ts`: a failed chapter is recorded and the run
   keeps going, writes the ready chapters, then throws
   `narration failed for chapter N` (non-zero exit). Covered by the
   same test (partial chapters on disk, retry resumes).
5. `pipeline/kokoro.ts`: the retry loop drops the SDK error and
   always throws the generic `narration synthesize failed`.

## Round 2: word-level timings (owner add-on)

Martin wants read-along highlighting word by word, like Kindle or
Audible. A probe on Modal (kokoro 0.9.4, af_heart, L4) showed that
`KPipeline` results carry `tokens` with `text`, `whitespace`,
`start_ts` and `end_ts` in seconds relative to the result's audio.
Punctuation and curly quotes come back as their own tokens, while
"Mr.", "Oz’s" and "didn't" stay as one token each. Forced alignment is
therefore not needed. Requested changes:

1. Modal returns word tokens per span with chapter-absolute times.
   `clean()` no longer rewrites em dashes, because Kokoro reads them
   fine and the tokens should match the displayed text.
2. Core maps tokens to display offsets in the paragraph, robust to
   punctuation, quotes and apostrophes. Display words with no matching
   token get interpolated times.
3. The manifest carries the words per chunk, and the parser validates
   them.

### Fixes

1. `pipeline/modal/narrate.py`: `clean()` no longer rewrites em dashes
   (keeps the `_` removal). Each span carries `words` as
   `[text, t0, t1]` with chapter-absolute seconds (span start + running
   result offset + token ts, rounded to ms); tokens without a letter or
   digit, or with a null timestamp, are skipped. Verified with a
   stubbed scratch run over the probe fixture (15 words, absolute
   offsets, null filtering, multi-result offsets) plus `py_compile`.
2. `core/narration.ts`: `alignWords` maps tokens onto display words
   from `/[\p{L}\p{N}]+(?:['’][\p{L}\p{N}]+)*/gu`, compared on NFKD
   lowercase letters/digits with apostrophes dropped, in order with a
   lookahead of 3 either way; a compound token splits its time by
   character length, unmatched words interpolate between neighbours,
   and all times are clamped to the span and monotonic. Returned
   offsets are relative to `text`; the caller adds the chunk start.
   Covered by probe-fixture tests (all 15 words, Kokoro times kept)
   plus missing/extra/spelled-out-number/straight-vs-curly/compound/
   empty cases.
3. `core/narration.ts`: `chunks[i].w` is the flat
   `[start, end, t0, t1, ...]` array (paragraph-relative offsets,
   seconds), required and validated (multiple of 4, integer offsets in
   range, finite times in range +0.05, sorted starts). `activeWordAt`
   and `wordAt` added with tests.
4. `ensureChapterNarration` and `pipeline/kokoro.ts`: `synthesize`
   returns `spans` with `words`, validated strictly in kokoro.ts
   (3-element `[string, finite, finite]` entries); `w` is built with
   `alignWords`. `NARRATION_FORMAT` is 2, so the cache key changes.
   Fakes updated in the narration-cache, narrate, freshness, and
   server tests, and `pipeline/kokoro.test.ts` pins the validator
   (pass-through plus five malformed shapes, SDK errors hidden).
5. `docs/contracts/narration.md`: word timings documented (Kokoro
   source, alignment and interpolation rules, `w` layout, ~25 KB per
   chapter). `check:size` passes.

Gates: `npm test` 51 files / 446 tests green, `typecheck`,
`check:size`, `check:secrets`, `test:hooks`, and `py_compile` pass.
No real Modal or paid calls. One flake: the jsdom worker for
`core/epub.test.ts` failed to spawn twice under Node 20 (repo wants
22.x); the full suite is green on rerun, and that file is untouched.
