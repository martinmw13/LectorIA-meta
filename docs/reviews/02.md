## Findings

1. **Gitleaks checksum check is not a real pin** (should-fix), `.github/workflows/ci.yml:36-38`.
   Problem: the checksums file is downloaded from the same release as the tarball, so a compromised release defeats the check.
   Fix: replace the checksums download and grep with a hardcoded hash: `echo '<sha256>  gitleaks_8.28.0_linux_x64.tar.gz' | sha256sum -c -`.

2. **Actions pinned to tags, not SHAs** (should-fix), `.github/workflows/ci.yml:16,19`.
   Problem: `actions/checkout@v4` and `actions/setup-node@v4` are mutable tags and can change under the workflow.
   Fix: pin each to its commit SHA with a version comment, for example `uses: actions/checkout@<sha> # v4`.

3. **curl without fail flag** (nit), `.github/workflows/ci.yml:36-37`.
   Problem: without `--fail` an HTTP error page is saved and only fails later at the hash check, with a confusing message.
   Fix: use `curl -sSfLO` for both downloads.

4. **History mode skips the forbidden filename check** (nit), `scripts/check-secrets.mjs:188-196`.
   Problem: `scanHistory` scans added lines but never calls `isForbiddenFilename`, so a committed `.env.local` in history flags only if its content matches a rule.
   Fix: when a `+++ b/` header names a forbidden file, push one `forbidden-filename` finding for it.

5. **SECURITY.md overstates the checksum** (nit), `SECURITY.md:11`.
   Problem: "with a verified checksum" reads as a real pin, which finding 1 shows it is not.
   Fix: after finding 1, write "with a hardcoded sha256" instead.

6. **Public quota versus reject rule needs one line** (nit), `SECURITY.md:20-21` and `.env.example:2`.
   Problem: the env sample says the owner key funds "the public quota" while SECURITY.md says a request without a user key is rejected, so a reader cannot tell which traffic uses the owner key.
   Fix: add one line naming which traffic uses the owner key (public chat) versus BYOK traffic.
