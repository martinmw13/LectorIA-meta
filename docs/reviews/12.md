## Grok Bot review

Baseline on origin/main 7e4683f: 237 tests in 27 files. Branch after the
implementation run: 253 tests in 28 files, typecheck, check:size,
check:isolation, test:hooks, check-secrets --all and gitleaks all clean.

Part 2 (one selection path) reads right: `audibleTracks` is the only
`playlistOnly !== true` filter, `compareTrackId` the only id tie-break,
`rankScored` scores each track once, and `selectScheduled` owns tolerance,
keep-current and the min-track hold. `noteTrackEnded` checks the empty
style before excluding the ended id, and `bestRanked` returns null on an
empty eligible set, so the outcome is the same as before.

Findings:

1. Must. The rng call order changed. Before, `evaluateRandom` drew first
   (`pickRandomTrack` called `rng()`) and applied the min-track hold
   afterwards. `selectScheduled` now returns early under the hold, before
   it draws. The visible pick is the same, but a seeded rng now advances
   differently during a hold, and the brief asked for identical rng
   consumption. Fix: draw first, then apply the hold to a pick that is
   not the current track.
2. Should. `canSkip` now comes from the view built at dispatch time with
   the route signal of that moment. Before, it was recomputed on every
   render from `routeSceneId`. Between a route change and the next
   dispatch (sceneEntered or the 1 s tick), the button can be stale for
   up to one tick. Either confirm sceneEntered always follows a route
   change in the same effect pass, or note the bound in the contracts doc.

## Muse review, round 1

What this change does: every music decision moves out of `app/reader.tsx`
into pure `core/music-session.ts` behind `startSession`/`dispatch`, and
the pick path collapses into one scope filter (`audibleTracks`), one
tie-break (`compareTrackId`), one scorer (`rankScored`), and one draw
(`selectScheduled`). The reader keeps routing, fetch, prefs, volume/mute,
and the `Player` markup. Checked by reading both versions of every
touched file, running the suite (28 files, 253 tests, all green with no
existing test edited), a scratch rng-count probe, and greps for leftover
refs, secrets, and new routes.

Grok finding 1 (rng order): verified, kept below as finding 1.
Grok finding 2 (canSkip stale up to one tick): refuted as stated, see
finding 3. Every route change fires `sceneEntered` in the same effect
pass (`app/reader.tsx:121`, gated by observed-vs-route id), which rebuilds
the view with the fresh route signal. No contracts note needed.

1. Must. Seeded rng diverges during the min-track hold
   (`core/music-selection.ts:102-107`).
   - What this is: the old `evaluateRandom` drew first (`rng()` inside
     `pickRandomTrack`) and applied the hold after, discarding the pick.
     `selectScheduled` returns before the draw while the hold is active.
   - Problem: the audible pick is the same (no switch either way), but a
     seeded rng advances once per hold under the old code and zero times
     now. Every later draw then picks a different track. My probe:
     hold-active draw consumes 0 `rng()` calls; the old order consumed 1.
     The spec demands identical rng consumption.
   - Fix: draw first, then hold, keeping a pick that is not the current
     track (exactly what Grok proposed). One or two lines in
     `selectScheduled`.
   - If we skip it: deterministic playback drifts from `origin/main`
     after any hold, and no test can pin the sequence.
2. Should. No test pins rng consumption, so finding 1 can come back.
   - What this is: `core/music-session.test.ts` uses a constant
     `rng: () => 0`, which cannot tell draw-first from hold-first apart.
   - Problem: the one behavior the refactor most easily breaks (call
     order with identical visible picks) has no failing test.
   - Fix: one test with a counting rng asserting one call per draw and
     the agreed hold-path count after finding 1 lands.
   - If we skip it: the next refactor reorders the draw again silently.
3. Nit. `canSkip` is cached at dispatch instead of per render, so it can
   lag one pre-effect render after a route change (old code read the new
   route id during that render). Same-effect `sceneEntered` corrects it
   before paint matters. No action; recorded only to close Grok finding 2.
