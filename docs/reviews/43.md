# Review 43: skin-matched "Picture this" drawing slot

Source: docs/tasks/43-picture-this-draw.md and agent-logs/prompts/43-impl.md
plus agent-logs/prompts/43-impl2.md. Diff is `origin/main...HEAD` on branch
`picture-this-draw`. `blast-radius` is disabled in this workspace, so the
caller sweep below was done by hand with grep.

What this change does: the `loading` phase of the pane and inline figures
renders a new `PictureDraw` SVG that draws a skin-matched sketch
(engraving needle, watercolor blooms, ink doodle) with `role="status"` and
warm copy. When the card turns `ready`, a frozen still stays mounted under
the `<img>` (which starts hidden via `pic-waiting`) until the image loads,
then a one-shot skin reveal (<= 850 ms) plays and the drawing unmounts. The
old bordered pill becomes a frameless `PictureButton`, and the infinite
`pane-pulse` animation is gone.

1. Stale `loaded` flashes the wrong state on a cached ready picture
   (`app/folio/picture-draw.tsx:108-121`, `app/folio/image-pane.tsx:36`,
   `app/folio/use-pictures.ts:102`, `app/leer/scene-page.tsx:316`).
   What this is: `usePictureLoaded` resets `loaded` in an effect on `url`
   change, so for one render after a ready(A) to ready(B) swap it still
   reports the old value. `ImagePane` has no `key`, and a scene revisit is
   a cache hit that returns `{ phase: "ready" }` directly, so this path is
   reachable without passing through `loading`.
   Problem: turning to an already-pictured scene renders the new image
   with the `rv-` reveal class and no frozen drawing for a frame, then the
   effect fires and the drawing pops in while the image hides until `onLoad`.
   Fix: store the url next to the flag (reset synchronously when the url
   argument changes, or `key` the ready branch by `card.url`). Small change,
   nothing else moves.
   If we skip it: every revisit to a pictured scene plays a visible
   reveal-flash, drawing-pop-in, image sequence instead of paper-then-image.
2. Tests pin freeze but not accumulate or reduced motion
   (`app/folio/picture-draw.test.tsx:1-123`).
   What this is: the two tests assert paper-plus-status on load, rAF silence
   after the ready flip, immediate `<img>`, and drawing removal after load.
   Neither advances fake timers to show stroke count only grows, nor renders
   with `matchMedia(matches: true)` to show the still plus the 200 ms fade.
   Problem: the round-2 headline fixes (accumulate, reduced-motion still)
   have no failing-when-broken coverage; a future change that reintroduces
   the 7 s wipe passes the suite.
   Fix: one test that steps the raf stub and asserts drawn-stroke opacity
   never returns to zero, and one with reduced motion asserting no rAF past
   mount and the `rv-fade` path. Both fit the existing harness.
   If we skip it: the regressions round 2 was created for can return
   silently.
3. Header comment describes round 1, not the code
   (`app/folio/picture-draw.tsx:1-3`).
   What this is: "the parent mounts this in the loading phase and unmounts
   it the instant the image is ready" was true before round 2; now the
   parents keep a `frozen` copy mounted under the image until load
   (`image-pane.tsx:84-88`, `inline-figures.tsx:79-83`).
   Fix: one line saying the frozen still stays under the image until load.
   If we skip it: the next reader trusts the comment and reintroduces the
   blank flash the frozen layer exists to prevent.

## Round 3 review (orchestrator, no Muse)

Verdict: **approve**.

- Stale `loaded` flag: fixed. `usePictureLoaded` keys state by url and resets synchronously; stale load events are ignored (picture-draw.test.tsx covers the url swap).

- Popover: portalled to `document.body` at document coordinates from the selection range, so it doesn't depend on page structure (safe under the continuous-scroll rewrite). - CSS polish (orchestrator): feathered paper glow behind the boxless pill and 4 px more lift, so it stays legible over the line above.
- Timings (built app, mocked /api/images, 1.5 s poll): the image mounts about 1.8 s after the ready flag, which is bounded by the poll interval, not the animation. The drawing is removed about 400 ms later. Early arrival 1 s into the drawing: the drawing is removed 20 ms after the image mounts.
