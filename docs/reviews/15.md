# Review 15: request body cap on POST /api/images

Closes the follow-up from review 14: `handleImagesPost` called `await req.json()`
with no app-level size cap.

- `server/images/body.ts` `readBodyCapped` (8192 bytes): rejects early on a
  declared `content-length` over the cap, then streams the body with a hard
  byte limit and cancels the reader past it, so a missing or lying header
  cannot bypass the cap. Never throws; a stream error maps to `read_error`.
- Handler: `too_large` -> 413, `read_error` and bad JSON -> 400, all with the
  generic `MSG_BAD_REQUEST`. No raw error text reaches the client.
- Tests: exact limit, limit+1, oversize header, lying header, headerless
  stream, multi-chunk early abort, null body, stream error; handler 413/400 paths.
- One Muse review round: made the reader non-throwing on client abort.

Checks: typecheck, 278 tests, check:size, check:secrets, gitleaks. Verdict: merge.
