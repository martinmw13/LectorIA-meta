## Muse review, round 1

Re-read `origin/main...home` after the round-0 fixes (through 344e1e2):
the parser and its guards against the fflate source, every `app/home`
component, the manifest loader, the key field, and the copy. One person
uploads one book at a time and parsing runs in their own browser, so the
load that matters is a hostile or broken file, not many users at once.

Must
- M1: keyboard focus was lost when the drop zone unmounted. A keyboard
  user picks a file, parsing succeeds, the focused drop zone is replaced
  by the book card, and focus falls back to the page body with no
  announcement. The same happens on "Read with soundtrack", which swaps
  in the processing note. Fixed: the parsed and processing views render
  in a `tabIndex={-1}` wrapper that an effect focuses on entry, so
  screen readers land on the result. In c045a11.

Should
- S1: dark-mode contrast misses AA for two text colors, measured: the
  error red is 2.9:1 and accent-colored links are 3.9:1 on the dark
  surface (light mode passes at 6.5 and 4.8). This comes from the shared
  palette, and tokens are frozen while the folio branch owns them, so no
  change here. Revisit the palette after that merge.

Nit
- N1: dragging a file across the drop-zone text flickers the highlight,
  because pointer moves over the child label fire leave events on the
  zone. Self-corrects on drop; leave it.
- N2: the NCX media-type check lists `application/x-dtbnc+xml` next to
  the correct `application/x-dtbncx+xml`. Harmless defensive extra;
  leave it.
- N3: the title filter would drop a chapter literally sharing its
  untitled book's "Untitled" name. Absurd edge, rule as specified;
  leave it.

Fixed
- `app/home/upload.tsx`: result wrapper with `tabIndex={-1}` plus an
  effect that focuses it when the parsed or processing view mounts
  (M1, in c045a11).

Security read, confirmed by hand: the key stays in React state with
`type=password`, `autoComplete="off"`, and a non-password-manager name;
it is cleared on submit and vanishes with the component on reset, never
stored, logged, or put in a URL. The inflate filter gets the declared
`originalSize` from fflate before each entry inflates and skips anything
over 8 MB; fflate pre-allocates from that declared size, so a lying
header fails the inflate instead of eating memory, and the 60 MB total
cap still applies. EPUB text renders through React only, never
`innerHTML`. Copy has none of the banned words; every file passes the
size hook.

Verdict: clean.

Not checked: clicked-through browser states (no `next start`/`dev` in
this task); `core/epub.test.ts` cannot start its jsdom worker on this
box (Node 20, jsdom 30 needs Node 22+; fails identically on the clean
tree), so the new filter test was verified with a standalone logic
probe instead — it should run in CI.

## Fix round 2

Bug: the "Start reading" link button rendered as a blue box with
invisible text, in light and dark (same for "Read Oz instead" in the
processing state). Cause: `.home-root a, .home-root a:visited`
(specificity 0,1,1) beat `.home-button` (0,1,0), so the label took the
accent color on the accent background; hover had the same problem.
Fix: an `a.home-button` override in `app/home/home.css` for link,
visited, hover, and focus keeps the on-accent text color. Plain links
keep the accent color. Resolved by 363d29f.
